2. Detailed timer descriptions

Configuration values below reflect the attached code. Values defined in missing project headers are explicitly identified.

TIMER0

OutputLTC

Configured with TIMER_PRESCALER=999; slave restart mode, trigger ITI0; update DMA enabled. Period = ((frame_ticks / (80×2)) − 1), assuming encoder kFormatSizeBits=80 (the exact constant is in an unavailable header). DMA1 CH5 writes 32-bit GPIO BOP words in circular double-buffer mode; two buffers live in .sram1. TIMER0SetType has a suspicious mask expression TIMER_CTL0(TIMER0) &= TIMER_CTL0_CEN rather than clearing CEN; review before testing.

TIMER2

InputLTC

PA6 / AF2, CH0 input capture, both-edge polarity, filter 0x3, 1 MHz prescaler macro TIMER_PSC_1MHZ, 16-bit auto-reload. ISR computes unsigned 16-bit capture difference and decodes LTC pulse widths; enabled only for LTC input.

TIMER3

SharedLTC / system time / internal

Master frame timer: TIMER_PRESCALER=999, frame auto-reload from kTmrIntv[type], update TRGO, priority-0 update IRQ. ISR marks timecode_available, increments timecode_counter and manages DMA waveform buffer copying. The frame clock is used by both internal and system-time source processing.

TIMER4

OutputPixel RTZ

Pixel master; prescaler=0, period pixel::kRtzTimerPeriod (comment: 1.25 µs), TRGO from CH0. CH0 DMA sets output, CH2 DMA conditionally clears from data_buffer, CH3 DMA clears output; GPIO transfers are synchronized to channel compares.

TIMER5

SystemSystem timing

Only described in timers.txt as “Delay micros”. No TIMER5 configuration or ISR appears in the supplied implementation files, so prescaler, resolution and ownership cannot be verified.

TIMER6

SystemStatistics

TIMER6_IRQHandler handles update events: updates_per_second = updates − updates_previous, updates_previous = updates, and increments gv_seconds.uptime. Its configuration is outside the attached files; timers.txt identifies the intended one-second cadence.

TIMER7

OutputPixel RTZ

Pixel slave: prescaler=0, external clock mode 0, trigger ITI3, compare CH0 at 1 + kBufferSize, IRQ priority 0. During Update() TIMER7 is reset and enabled with TIMER4; compare IRQ stops TIMER4 and disables pixel DMA requests. TIMER7 period is configured UINT32_MAX.

TIMER8

InputMIDI

Listed as MIDI Active Sense in timers.txt. No TIMER8 register setup, ISR, or timeouts can be verified from attached sources.

TIMER9

InputDIN / Apple MIDI

Configured with TIMER_PRESCALER=999 and frame period kTmrIntv[type]. IRQ TIMER0_UP_TIMER9 priority 2; ISR increments/distributes timecode then disables its update interrupt. Used in MIDI input path.

TIMER10

OutputDIN / Apple / USB MIDI

Configured with TIMER_PRESCALER=999, update IRQ TIMER0_TRG_CMT_TIMER10 priority 0. Period = ((frame_ticks / 4) − 1). Emits intermediate MIDI quarter-frame messages; the first piece is sent during frame distribution.

TIMER13

OutputMIDI Clock

Configured with TIMER_PSC_10KHZ. SetBpm computes CAR = ((25000 + BPM/2) / BPM) − 1, rounded integer division, giving 10,000 × 60 / (24 × BPM) ticks per MIDI Clock. BPM=0 stops the counter; update ISR emits MIDI Clock.

3. Protocol-by-protocol input/output timer usage

LTC input

InputTIMER2

TIMER2 CH0 captures both edges on PA6 with 1 µs nominal resolution; ISR computes 16-bit wrapped delta and decodes bi-phase mark timing. TIMER3 is the shared frame master used downstream for output distribution.

LTC output

OutputTIMER3 + TIMER0

TIMER3 generates frame-boundary update IRQ/TRGO; TIMER0 is restart-triggered via ITI0 and generates update DMA requests through DMA1 CH5. Double-buffered GPIO BOP data produces the LTC waveform.

MIDI Time Code input

InputTIMER9

DIN MIDI and Apple MIDI input handlers use TIMER9 for timecode pacing/interpolation after incoming MTC. This is distinct from TIMER2 LTC electrical decoding.

MIDI Time Code output

OutputTIMER10

TIMER10 schedules MIDI quarter-frame messages at nominal frame-period/4. The same scheduler serves DIN MIDI, Apple MIDI and USB MIDI when enabled.

MIDI Clock / BPM

OutputTIMER13

TIMER13 generates MIDI Clock events (24 pulses per quarter note) based on the selected BPM; disabling BPM stops the timer.

Pixel output (RTZ)

OutputTIMER4 + TIMER7

TIMER4 channel compare DMA sets the GPIO high then conditionally clears it at 0/1 bit widths. TIMER7 counts master triggers and interrupts at the end of the pixel transfer.

Internal timecode

Logical inputTIMER3 (shared)

The internal source consumes the global frame-available flag produced by TIMER3; it increments/decrements timecode and supports pitch adjustment. It does not configure a dedicated timer.

System-time source

Logical inputTIMER3 (shared)

System time initializes the running timecode; the active Run() uses global timecode_counter generated by TIMER3 to advance frames and reports missed frame ticks.

System / diagnostics

SystemTIMER5 + TIMER6

TIMER5 is assigned to microsecond delay by timers.txt only. TIMER6 provides one-second uptime and output update-rate accounting.

MIDI Active Sensing

InputTIMER8

The timer inventory assigns TIMER8 to MIDI Active Sensing. Configuration, timeout and interrupt implementation are not present in the supplied files.

4. Timing formulas and frame rates

Common timecode tick

MASTER_TIMER_CLOCK = AHB_CLOCK_FREQ
TIMER_PRESCALER = 999
FREQUENCY_EFFECTIVE = AHB_CLOCK_FREQ / 1000

Frame timer

kTmrIntv[fps] = floor(FREQUENCY_EFFECTIVE / fps) − 1
Supported frame-number bases: 24, 25, 30, 30 (DF).

MIDI quarter frame

CAR10 = floor((kTmrIntv+1)/4) − 1
Four quarter-frame intervals per LTC frame.

MIDI Clock

CAR13 = floor((25000 + BPM/2)/BPM) − 1
24 clock messages per beat at 10 kHz.

Integer division truncates non-integral frame intervals. At a nominal AHB clock of 200 MHz, the effective timecode clock is 200 kHz; 24 fps gives 8,333 ticks (41.665 ms), 25 fps 8,000 ticks (40 ms), and 30 fps 6,666 ticks (33.330 ms). These are examples, not verified runtime clock settings. Drop-frame uses a 30-frame numbering base; its exact wall-clock correction is a separate issue.

5. Implementation observations / verification points

TIMER0 enable-mask: TIMER_CTL0(TIMER0) &= TIMER_CTL0_CEN in Timer0SetType() preserves CEN and clears other control bits; check whether &= ~TIMER_CTL0_CEN was intended.

Timer trigger documentation: the LTC comment describes TIMER3 → TIMER0, while actual code selects TIMER_TRI_OUT_SRC_UPDATE and TIMER_SMCFG_TRGSEL_ITI0. The MCU trigger matrix should be checked against the specific GD32 part.

Missing definitions: pixel::kRtzTimerPeriod, pixel::kT0H, pixel::kT1H, ltc::encoder::kFormatSizeBits, and TIMER_PSC_10KHZ are in headers not provided; do not assume exact tick values from these files alone.

TIMER5 / TIMER8 / TIMER6 setup: inventory or IRQ behavior is present, but full timer initialization is not supplied. Treat these allocations as partial documentation.

Pixel DMA routing: source uses board macros TIMER4_*DMA*; timers.txt names DMA0 CH2 / CH0 / CH1 for TIMER4 CH0 / CH2 / CH3. Verify macro expansion against the target board.

System-time missed ticks: active system-time Run() detects elapsed counters greater than one, but increments the timecode only once before reporting the missed frames.

Drop-frame reverse: timecode::Decrement() contains a placeholder comment for drop-frame handling; this is relevant to reverse internal playback, not a hardware timer allocation.
