System Time Architecture

Firmware source review · RTC, GPS/GNSS PPS, NTP client using Ethernet PTP hardware, and NTP server output.

The RTC and shell command implementations are not included in the supplied files. Their startup and command behavior therefore cannot be independently verified from this attachment set. GPS and PTP-NTP flows below are supported by implementation code.

2. Three sources of time

Source Trigger / operation What is verified
RTC / shell Boot initialization; manual shell commands Requested architecture, but RTC boot initialization and shell handlers were not supplied. Exact precedence and persistence cannot be confirmed.
GPS / GNSS GNSS receiver obtains date/time; rising PPS GPIO interrupt ltc::gps::Start() starts receiver, PPS EXTI and UDP GPS control. PPS ISR calls settimeofday() with LocalSeconds()+1, then the LTC synchronization callback.
NTP client / PTP Network NTP replies, hardware timestamp processing PTP-backed client computes an offset, calls Gd32PtpUpdateTime(), reads PTP time and calls ptp::systime::TimeUpdated() unless disabled at compile time. This is an NTP client using PTP hardware timestamps, not proof of a separate IEEE 1588 network slave.

3. GPS and NTP client arbitration

Action GPS NTP client Explanation
GPS Start Starts Stops ltc::gps::Start() explicitly calls ltc::ntpclient::Stop().
GPS Stop, NTP server disabled Stops Starts GPS Stop checks Destination::IsDisabled(kNtpServer) before restarting client.
GPS Stop, NTP server enabled Stops Remains stopped The conditional restart is skipped.
NTP client Start while GPS running Runs Does not start ltc::ntpclient::Start() immediately returns if gps::IsRunning().

4. NTP server enabled: verified behavior

Important correction: The statement “when NTP server is enabled, GPS and NTP client are not running” is not fully supported by the provided code. The NTP client is explicitly stopped; GPS is not stopped by the server Start path. 
ltc::ntpserver::Start():
    ltc::ntpclient::Stop();
    ltc::network::ntpserver::Start();

// No ltc::gps::Stop() call in this function.

Enabling the NTP server through Destination::Enable(kNtpServer) invokes that Start callback. GPS may remain active if it was already running; its PPS interrupt may continue to update system time. The network NTP server implementation itself is not attached, so its response timestamp source cannot be independently verified.

5. NTP server disabled: verified behavior

Verified: Disabling the NTP server stops the server and attempts to restart the NTP client. Whether the client actually starts depends on GPS state, compile-time configuration and client/server configuration. 
Destination::Disable(kNtpServer)
  └─ ntpserver::Stop()
       ├─ ltc::network::ntpserver::Stop()
       └─ ltc::ntpclient::Start()
            ├─ if GPS IsRunning(): return (no NTP client)
            └─ otherwise:
                 ├─ standard NTP client: Stop(false), Start()
                 └─ PTP-backed NTP client: Stop(false), Start()
                    (selected by CONFIG_NET_ENABLE_* macros)
Situation after disabling NTP server Result
GPS running GPS remains time source; NTP client Start returns without starting.
GPS stopped; PTP NTP client compiled and server IP configured PTP-backed NTP client is restarted and attempts network synchronization.
GPS stopped; no configured NTP server IP PTP NTP client Start sets status Stopped; it cannot begin polling.
Client implementation excluded at compile time No corresponding network client starts.

6. System time to LTC timecode

ltc::input::systime::Start() selects SMPTE when the output type is unknown, reads local time via ltc::timecode::LocalTime() and initializes the timecode with ltc::timecode::Set() . In Run() , changes in timecode_counter cause the current timecode to be distributed, then incremented. The code reports missed increments if the elapsed counter differs from one.

GPS PPS invokes network::apps::ntpclient::systime::TimeUpdated() ; standard NTP uses the same callback, while PTP-backed NTP uses network::apps::ntpclient::ptp::systime::TimeUpdated() . Both call ltc::timecode::Sync() only when the selected LTC input is Input::kSystime . The Ethernet PTP second interrupt also calls Sync under the same selection condition. The selected LTC input is separate from the system-clock synchronization source.

7. Ethernet PTP second interrupt

network::event::Ipv4AddressChanged() invokes network::ptp::pps::Start() , which schedules a hardware PTP timestamp interrupt. ENET_IRQHandler() reschedules the next second and synchronizes LTC timecode when the system-time LTC input is selected. ntpclient::StatusChanged(kLocked) resets the PTP second trigger when the PTP-backed client is configured.

8. State transition summary

Event Consequence
Start GPS Stop NTP client; activate GNSS receiver and PPS ISR.
Stop GPS Deactivate GPS; restart NTP client only if NTP server output is disabled.
Enable NTP server Stop NTP client; start NTP server; GPS state unchanged.
Disable NTP server Stop NTP server; request NTP client start, which is vetoed while GPS runs.
Select LTC system-time input Initialize LTC timecode from local clock; accept clock-to-timecode sync callbacks.

9. Review observations and limitations

  1. GPS exclusion is not symmetrical. NTP client Start checks GPS, but NTP server Start does not stop GPS. If server mode must exclude GPS, add an explicit policy and stop GPS deliberately; beware that GPS Stop may restart the client depending on the server enabled flag.
  2. Server disable is conditional. It does not guarantee a running NTP client. GPS, build flags and missing server IP can prevent that.
  3. Server implementation missing. The ltc::network::ntpserver::Start/Stop internals, actual NTP replies, and their time source cannot be audited.
  4. RTC and shell missing. To verify boot RTC restore, hwclock commands and exact clock updates, review their implementations and startup wiring.
  5. Possible state issue to test. The PTP client Stop(true) sets Disabled, while its Start() returns when Disabled; the wrapper first calls Stop(false). Confirm the state transitions in a live test when disabling NTP server, particularly whether Disabled is cleared before Start.
  6. Time domains. GPS PPS writes settimeofday(); PTP NTP client adjusts Ethernet PTP hardware time. Confirm system-clock/PTP-clock coupling in the underlying clock implementation before claiming they are identical.
