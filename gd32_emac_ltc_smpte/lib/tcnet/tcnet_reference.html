1. Receiver overview and defaults

The firmware acts as a TCNet receiver: UDP 60000 accepts management traffic; UDP 60001 accepts Time packets (message type 254). An Opt-IN broadcast is sent every 1000 ms to UDP 60000. Firmware controls are separate from the TCNet wire protocol.

Setting Initialized value Purpose
Node name AvV 8-byte Opt-IN identification field
Layer kLayerM Chooses layer-specific time fields
Use embedded timecode false False: milliseconds; true: six-byte SMPTE timecode
Conversion type kSmpte30Fps Default nominal 30 fps for millisecond mode

Init() sets these defaults, and is called on first Start() . Subsequent Start/Stop cycles retain settings. Start() registers UDP listeners and the periodic Opt-IN timer; Stop() closes the listeners and deletes the timer.

2. Node name — fixed-width wire field

SetNodeName(const char*) writes all eight bytes of management_header.node_name . It fills the field with spaces, then copies up to eight bytes of the supplied name. No NUL terminator is reserved in the wire field. 

				assert(node_name != nullptr);
auto* destination = packet_opt_in.management_header.node_name;
memset(destination, ' ', sizeof(packet_opt_in.management_header.node_name));
const auto length = strnlen(node_name, sizeof(packet_opt_in.management_header.node_name));
memcpy(destination, node_name, length);

NodeName() returns an eight-character std::string_view (including trailing spaces). Print() uses %.8s . Precondition: the pointer must be non-null and readable; assert is not a runtime guard when NDEBUG is defined. No node-name control command is exposed in the supplied action dispatcher.

3. Layer selection and offsets

SetLayer() rejects values at or beyond kLayerUndefined , then computes offsets from offsetof(packet::Time, L1Time) and offsetof(packet::Time, L1TimeCode) .

The eight millisecond fields are 32-bit; embedded timecode fields are six bytes: smpte_mode, state, hours, minutes, seconds, frames . Both are selected using the same layer index. This table describes the packed structure supplied in tcnet_packet.h .

4. Two receive paths and SMPTE mode fallback

Setting Source Processing
SetUseTimeCode(true) Selected layer's six-byte embedded timecode Copies HH:MM:SS:FF; chooses SMPTE type from layer mode or packet-level fallback
SetUseTimeCode(false) Selected layer's 32-bit millisecond value memcpy, modulo 86,400,000, split into HH:MM:SS and fractional frame using kFps

Current embedded-mode precedence

				auto smpte_mode = lx_tc->smpte_mode;
if (smpte_mode < 24) {
    smpte_mode = packet_time.SMPTEMode;
}
// 24 -> Film; 25 -> EBU; 29 -> DF; 30 -> SMPTE;
// all other values -> SMPTE 30 fps.

What this means: values 0..23 in the layer's smpte_mode are treated by this implementation as a signal to consult the packet-wide SMPTEMode at offset 105. This is a code-level fallback rule, not a verified statement about the TCNet specification's meaning of values below 24.

Important distinction: the subsequent switch maps any mode other than 24, 25 or 29 to 30 fps, including unrecognized values above 30 and an invalid packet-wide fallback. IsValid(timecode) cannot detect the original invalid mode because it sees the already-normalized type 3.

Documentation recommendation

				// Compatibility policy: a layer SMPTE mode below 24 uses
// the packet-wide SMPTEMode field as a fallback.
// Accepted modes: 24, 25, 29, 30.
// Unknown modes currently default to 30 fps.
// Confirm these fallback semantics against the TCNet specification
// and actual transmitter behavior before changing them.

Document the reason for the < 24 threshold once it is established (e.g., transmitter compatibility or a defined protocol sentinel). Until then, mark it as implementation behavior rather than a normative protocol requirement.

5. Frame-rate selection and validation

Type Numeric value Control argument Nominal frames per second
Film 0 24 24
EBU 1 25 25
Drop-frame 2 29 30 frame labels (29.97 real rate)
SMPTE 3 30 30

kFps[] = {24,25,30,30} , matching the supplied TimeCodeConst::kFps . A compile-time assertion checks the array length against the last valid enum. SetTimeCodeType() rejects enum values above kSmpte30Fps , avoiding out-of-range lookup in normal initialized operation.

IsValid() rejects hours ≥24, minutes/seconds ≥60, types ≥4, frames ≥ nominal fps, and DF frame labels 00/01 at second zero of non-tenth minutes. The receive callback validates before updating the previous-timecode cache and distributing.

Limitation: millisecond conversion uses floor(fractional_ms * 30 / 1000) for DF, but does not generate drop-frame numbering or correct 29.97 elapsed-time mapping. Applying IsValid() may therefore discard generated DF timecodes at the start of non-tenth minutes. Embedded timecode is the preferable DF source until a dedicated converter exists. ltc::timecode::Decrement() also contains an unfinished drop-frame handling comment in the supplied LTC header.

6. Firmware control paths

Three paths reach the TCNet action setters. The exact shared action-prefix values are defined in ltc_commands.h , which was not among these attachments, so they are shown symbolically rather than guessed.

Transport Routing established by source TCNet actions
Firmware UDP UDP callback accepts tcnet!, then passes the remainder to ltc::actions::tcnet::HandleAction() kLayer, kType, kTimecode
Shell shell::ltc::TCNet(args) requires two tokens, forwards args[1] to HandleAction() Same shared actions
OSC Path prefix /<hostname>/tc/, then tcnet/layer/, tcnet/type/ or tcnet/timecode/ Dedicated setters called directly

Layer accepts one of 1 2 3 4 a b m c (case-insensitive through LayerFromChar ). Type accepts two characters parsed as 24, 25, 29 or 30. Timecode mode accepts exactly one character: lowercase y enables embedded mode; any other single character disables it. The latter is not strict y/n validation.

TCNet wire traffic uses UDP 60000 and 60001. Firmware-specific control commands are separate; the UDP control port number is declared in the unattached ltc_udp_port.h and is not reverified here. OSC uses its own configured UDP listener.

8. TCNet timecode pointer lifetime — reviewed 12 October 2026

Recommendation: retain the local ltc::TimeCode in tcnet::Handle() . A five-byte stack object remains alive for the entire synchronous Distribute() invocation. Using static does not establish correct asynchronous ownership: a later packet could overwrite the same object while a consumer is still using it. 

				void Handle(const tcnet::Timecode* timecode_tcnet) {
    ltc::TimeCode timecode;
    std::memcpy(&timecode, &timecode_tcnet->frames, sizeof(timecode));
    // Callees must consume or copy data before returning; do not retain pointer.
    ltc::output::Destination::Instance().Distribute(&timecode);
}

Call-path evidence

Function / output Observed behavior Lifetime assessment
Destination::Distribute() Calls enabled LTC output, enabled Art-Net output, then DistributeInternal() inline. No pointer saved in the dispatcher.
ltc::output::ltc::Output() Calls encoder::SetTimeCode<false>(), encodes into selected DMA buffer, adjusts timer. The shown code does not retain the caller pointer; encoder internals were not provided.
Destination::DistributeInternal() Uses fields for timer/MIDI, NTP and display operations; formats timecode into owned timecode_ text. No retained pointer visible in this function; delegated callees need separate review.
USB MIDI inline output Builds a local USB MIDI packet and calls usbmidi::Send(). Original timecode pointer is not retained by the inline wrapper; USB send internals not supplied.
Art-Net, ETC, native MIDI, RTP-MIDI, NTP Headers or wrappers supplied, but not all final output implementations. Do not claim end-to-end proof of no retained pointers without inspecting these implementations.

Recommended API contract

Document Distribute(const ltc::TimeCode*) as a borrowed pointer valid only for the duration of the call. Every output must read or copy the timecode before returning; asynchronous DMA/network work must own its data. A reference-based API ( const ltc::TimeCode& ) can make borrowing clearer but does not by itself prevent retention.

Additional observation: DistributeInternal() still reinterprets ltc::TimeCode* as midi::Timecode* in MIDI branches. This is a separate aliasing/layout review item, not a stack-lifetime issue.
