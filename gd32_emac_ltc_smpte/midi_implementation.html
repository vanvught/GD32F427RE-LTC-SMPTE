MIDI Implementation — LTC Firmware

Source-based reference for MIDI Time Code (MTC), MIDI Clock, DIN MIDI, AppleMIDI/RTP-MIDI and USB-MIDI. Structured around the signal-flow examples in midi.txt . This describes the supplied implementation, not every feature of the MIDI standard.

The input source is selected through ltc::input::Source ; the corresponding Start() , Stop() and (where needed) Run() functions are dispatched by the input table. Only the selected AppleMIDI source is accepted by its RTP callback.

2. Transports

Transport Input handling Output handling Notes
DIN MIDI UART RX interrupt timestamps bytes and enqueues them; midi::Run() parses them. UART transmit of Full Frame SysEx, QF and realtime bytes. 31,250 baud, 8 data bits, no parity, 1 stop bit.
AppleMIDI UDP session establishment; RTP-MIDI decoder calls rtpmidi::MidiMessage(). AppleMIDI output routines are called for Full Frame and QF. Session invitations, synchronization and timeout are implemented.
USB-MIDI usbmidi::Message() supplies USB events; Run() switches on CIN. Full Frame and QF sent through USB MIDI output API. USB endpoint queue internals are not present in the attached source.

3. MTC Quarter Frame input

DIN: F1 xx ───────────────┐
AppleMIDI: type F1 + xx ─┼──► mtc::HandleQuarterFrame(xx)
USB: CIN 02, F1 xx ──────┘                 |
                               pieces 0 ... 7 assembled
                                         |
                                  piece 7 received
                                         |
                              copy to timecode_running
                                         |
                                    Distribute()
                                         |
                                TIMER9 configured

The eight 4-bit pieces assemble frames, seconds, minutes, hours and the frame-rate type. On piece 7, the decoded timecode is distributed and Timer9Set(type) arms a one-frame interpolation interval. The TIMER9 interrupt increments and distributes once, then disables its update interrupt until rearmed.

4. MTC Full Frame input

DIN SysEx ──────┐
AppleMIDI SysEx ├──► transport-specific decoding
USB SysEx ──────┘                |
                       mtc::HandleFullFrame(
                         hours, minutes, seconds, frames)
                                 |
                         update timecode_running
                                 |
                              Distribute()

Full Frame format: F0 7F 7F 01 01 hr mn ss ff F7 . The upper bits of hr encode the MTC type; the lower five bits encode the hour. Unlike Quarter Frame completion, HandleFullFrame() does not call Timer9Set() .

6. MTC output generation

DistributeInternal(timecode)
          |
          +-- type changed? --> send MTC Full Frame to enabled MIDI outputs
          |
          +-- CreateQuarterFrame() for initial QF piece
          |       |
          |       +--> DIN / AppleMIDI / USB-MIDI
          |
          +-- TIMER10 set to quarter-frame interval
                      |
               TIMER10 interrupt
                      |
               CreateQuarterFrame()
                      |
               DIN / AppleMIDI / USB-MIDI

CreateQuarterFrame() cycles pieces 0–7. TIMER10 supplies the quarter-frame timing; pieces 0 and 4 are handled at the frame distribution boundary rather than sent from the timer ISR. A type change resets the QF state and sends a Full Frame message to each enabled MIDI output.

The supplied midi.txt also illustrates USB transmit queue, busy state and endpoint completion. Those details cannot be independently verified from the attached USB driver files because the USB driver implementation was not included.

7. MIDI Clock / BPM

DIN 0xF8 ────────┐
RTP-MIDI Clock ──┼──► CalculateBpm(timestamp, received, bpm)
USB CIN 0F / F8 ─┘                   |
                            accumulate 24 deltas
                                    |
                           BPM = round(60,000,000
                                      / delta_sum)
                                    |
                             DisplayBpm(bpm)

No clock for 1,000,000 microseconds --> reset BPM state; DisplayBpm(0)

DIN and USB use timing::Micros() timestamps (DIN captured on reception); AppleMIDI uses RTP timestamp multiplied by 100 for calculation and local microseconds for timeout tracking. The calculation reports a changed BPM once per 24 MIDI Clock intervals. A zero delta is ignored; a delta of at least one second resets the accumulation.

Parameter Value / behavior
MIDI Clock message 0xF8
Calculation window 24 intervals (one quarter note at 24 PPQN)
BPM formula (60000000 + delta_sum / 2) / delta_sum (integer rounding)
Display timeout 1,000,000 µs without a clock
Configured output BPM range 8–300 BPM (midi.h)
Generated clock TIMER13 sends midi::Type::kClock via Destination::MidiSend()
Timer period register CAR = ((25000 + bpm / 2) / bpm) - 1 with a 10 kHz timer base

8. MIDI realtime controls

MIDI byte Type Implementation
FA Start Action dispatch to MidiSend(kStart)
FB Continue Action dispatch to MidiSend(kContinue)
FC Stop Action dispatch to MidiSend(kStop)
F8 Clock Input BPM measurement; output generated by TIMER13
FF Reset DIN parser returns to idle

A UDP control handler accepts messages beginning with midi! , then forwards the remainder to ltc::actions::midi::HandleAction() . It recognizes start, stop, continue and BPM command prefixes defined in ltc_commands.h , which was not attached; therefore their exact wire strings are not reproduced here.

9. Timer overview

Timer Role Behavior
TIMER9 MTC input interpolation Armed after complete QF assembly; one increment and distribution on update.
TIMER10 MTC output QF scheduling Quarter-frame cadence, coordinating pieces with frame boundaries.
TIMER13 MIDI Clock output 10 kHz base, BPM-derived period, sends realtime Clock.
TIMER3 Core LTC frame timing Master frame timing in LTC output implementation.
TIMER0 LTC waveform output DMA-driven LTC waveform timing; not a MIDI parser timer.

10. AppleMIDI / RTP-MIDI

AppleMidi implements invitation/accept/reject/end-session messages and timestamp synchronization. Session establishment proceeds through control and MIDI invitations, then accepts RTP-MIDI messages. An established session has a 90-second timeout managed by a software timer. RtpMidi decodes the RTP command section, delta times and supported MIDI status bytes, and forwards parsed midi::Message objects to rtpmidi::MidiMessage() .

The RTP callback handles QF, Full Frame SysEx and Clock only when the selected LTC input is AppleMIDI. The parser contains other MIDI status types, but they are not thereby LTC input features.
